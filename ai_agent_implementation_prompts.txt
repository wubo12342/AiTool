# AI Agent 智慧小幫手實作與設計規範

這份文件定義了本專案 AI Agent 的核心邏輯與工具設計。請依照以下規範引導 AI 進行開發。

---

## 一、 核心開發四原則 (Consensus)

1. **智慧選取 (Tool Selection)**：AI 接收使用者問題後，根據「工具說明書」中的簡介（包含分類、功能、適用場景）自主判斷要調用哪一個 Tool。
2. **語義對齊 (Enum Constraint)**：在工具定義中明確使用 `enum` 鎖定資料庫的「分類」與「標籤」。若使用者需求不完全匹配，AI 必須自動對應到最接近的母分類，並將具體需求放入 `keyword` 參數中，防止 SQL 查詢因名稱不符而失效。
3. **範本查詢 (SQL Templates)**：AI 嚴禁從頭撰寫原始 SQL 語法。AI 僅負責提取參數（變數值），由 PHP 後端將參數填入預先寫好的 SQL 樣板中執行，以確保系統安全性 (防範 SQL Injection) 與穩定性。
4. **增強生成 (Fake RAG)**：後端執行 SQL 後回傳的原始資料（JSON），需再次餵回給 AI。AI 扮演「專業顧問」角色，根據這些數據進行總結、比較與推薦，生成最終對使用者友好的回覆。

---

## 二、 Agent 工具集定義 (Tools Design)

### 1. smart_search (智慧條件搜尋)
- **描述**：當使用者尋找、推薦或探索不認識的工具時使用。
- **參數**：
    - `category` (Enum): [圖像生成, 影片剪輯, 文本寫作, 程式助手, 辦公效率]
    - `keyword` (String): 使用者的具體需求關鍵字。
- **後端 SQL**：`SELECT * FROM ai_tools JOIN categories ON ... WHERE categories.name = ? AND (description LIKE ? OR tags LIKE ?)`

### 2. get_personal_context (個人化偏好讀取)
- **描述**：在對話開始或需要精準推薦前，讀取使用者的職業背景與偏好。
- **數據來源**：`user` 表中的 `system_prompt` 欄位。
- **場景**：使用者問「推薦適合我的工具」時優先觸發。

### 3. get_community_insights (社群口碑總結)
- **描述**：抓取工具評論並進行正反面分析。
- **策略**：回傳「最新 3 筆」+「評分最高 2 筆」+「評分最低 2 筆」訊息，總量不超過 10 筆。
- **數據來源**：`tool_reviews` 表。

### 4. pricing_comparison_expert (價格方案分析)
- **描述**：解析工具的 `pricing_plans` (JSON 格式)，比較多款工具的訂閱成本。
- **數據來源**：`ai_tools` 表中的 `pricing_plans` 欄位。

### 5. trending_tools_retriever (熱門趨勢查詢)
- **描述**：查詢目前平台收藏數最多的工具榜單。
- **後端 SQL**：`SELECT tool_ID, COUNT(*) FROM user_likes GROUP BY tool_ID ORDER BY COUNT(*) DESC LIMIT 5`

---

## 三、 Agent 運作流程 (The Loop)

1. **[User Input]**: 使用者傳送訊息。
2. **[Thought]**: AI 分析意圖，決定需要哪些資料。
3. **[Action]**: AI 輸出 JSON 格式的 Tool Call 指令（例如 `search_tools`）。
4. **[Observation]**: PHP 接收指令 -> 執行對應 SQL 樣板 -> 獲取資料庫結果 -> 將 JSON 結果回傳給 AI。
5. **[Final Response]**: AI 讀取資料庫數據，結合「個人化偏好」，生成最終的建議回覆給使用者。

---

## 四、 錯誤處理規範
- 若 `smart_search` 回傳為空，AI 應自動嘗試「擴大搜尋範圍」或建議使用者更換關鍵字。
- 嚴禁 AI 在回覆中直接顯示資料庫的 ID 欄位，應以名稱與 Logo 連結取代。
